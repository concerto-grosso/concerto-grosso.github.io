《Linux/UNIX系统编程手册》第59章 套接字：互联网域

发表于 2026-08-15 更新于 2026-08-19 分类于 Linux 本文字数： 13k

　　互联网域流套接字被实现为基于TCP，它提供了可靠的双向字节流通信通道。

　　互联网域数据报套接字被实现为基于UDP，它类似于UNIX域数据报套接字，但两者存在以下不同：

　　● UNIX域数据报套接字是可靠的，但UDP套接字不是可靠的 (数据报可能乱序、重复或丢失)。

　　● 若接收套接字的数据队列已满，则通过UNIX域数据报套接字发送数据会阻塞进程。相比之下，当使用UDP套接字时，若传入数据会导致接收端的数据队列溢出，则该数据报被静默丢弃。

　　不同硬件架构存储多字节整数的顺序可能不同，这种字节顺序分为2类：大端和小端 (这些术语源于Jonathan Swift 1726年的讽刺小说《格列佛游记》，书中这些术语指代在煮熟的鸡蛋的两端打开的对立政治派别)，前者将最高有效字节存储在最低内存地址，而后者将最低有效字节存储在最低内存地址。x86和Digital的VAX架构使用的是小端模式，而大多数其他架构都是使用大端模式。有些硬件架构可以在这2种模式之间切换。特定机器的字节顺序称为主机字节顺序。

　　主机名是连接到网络的系统的符号标识符。服务名是端口号的符号表示。

　　● 主机地址可以通过二进制值、符号主机名或表示格式 (点分十进制IPv4地址或十六进制IPv6地址) 表示。

　　● 端口可以通过二进制值或符号名表示。

　　当编写通过网络通信的应用程序时，必须使用互联网域套接字。当使用套接字在同一系统上的应用程序之间通信时，仅使用互联网域套接字通常是最简单的方法，因为它既可以在单台主机上运行，也能在通过网络连接的不同主机上运行。但是，在这种情况下，相比互联网域套接字，UNIX域套接字存在以下优势：

　　● 对于某些实现，UNIX域套接字比互联网域套接字更快。

　　● 可以通过目录权限来控制对UNIX域套接字的访问，这样只有具有指定用户ID (或组ID) 的应用程序才能连接监听套接字或向数据报套接字发送数据报。这提供了简单的客户端身份验证方法。对于互联网域套接字，若需要对客户端进行身份验证，则需要做更多工作。

　　● 使用UNIX域套接字，可以传递打开的文件描述符或发送者凭证。
