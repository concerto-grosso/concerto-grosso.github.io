《Linux/UNIX系统编程手册》第60章 套接字：服务器设计

发表于 2026-08-22 更新于 2026-08-23 分类于 Linux 本文字数： 5.8k

　　迭代服务器每次仅服务1个客户端，当服务完该客户端之后，才会服务下一个客户端。并发服务器旨在同时服务多个客户端。

　　迭代服务器通常适合客户端请求能够被快速处理的场景，因为每个客户端必须等待前面的客户端都得到服务。使用这种设计的典型场景是客户端和服务器仅交换1个请求和1个响应。

　　并发服务器适合客户端请求需要大量时间来处理或客户端和服务器来回多次传递消息的场景。本章主要介绍并发服务器的传统实现方法：为每个客户端创建独立的子进程，这些子进程会在服务客户端后终止。服务器主进程的主要任务是为每个客户端创建1个子进程 (这种实现方法的变体之一是为每个客户端创建1个线程)。

　　文件/etc/services包含大量服务，这表示系统理论上可以运行大量服务器进程，但其中大部分只是等待不频繁的连接请求或数据报。尽管如此，这些服务器进程还是被记录在内核进程表中，并占用了部分内存和交换空间。

　　守护进程inetd旨在避免运行大量不常用的服务器，它有2个主要优势：

　　● 无需为每个服务运行单独的守护进程，inetd会监控指定端口号并按需启动服务器。因此，系统中运行的进程数减少了。

　　● 由inetd启动的服务器的编程得到了简化，因为该守护进程会执行所有服务器启动时通常需要执行的一些步骤。

　　守护进程inetd负责管理大量服务，并按需启动服务器，所以它也称为互联网超级服务器守护进程。

　　守护进程inetd的行为由配置文件控制，该配置文件通常是/etc/inetd.conf。

　　某些Linux发行版还提供了inetd的扩展版xinetd。除了其他功能之外，xinetd添加了很多安全增强功能。
