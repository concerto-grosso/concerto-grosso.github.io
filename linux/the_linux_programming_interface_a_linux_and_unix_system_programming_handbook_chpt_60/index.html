　　迭代服务器每次仅服务1个客户端，当服务完该客户端之后，才会服务下一个客户端。并发服务器旨在同时服务多个客户端。

　　迭代服务器通常适合客户端请求能够被快速处理的场景，因为每个客户端必须等待前面的客户端都得到服务。使用这种设计的典型场景是客户端和服务器仅交换1个请求和1个响应。

　　并发服务器适合客户端请求需要大量时间来处理或客户端和服务器来回多次传递消息的场景。本章主要介绍并发服务器的传统实现方法：为每个客户端创建独立的子进程，这些子进程会在服务客户端后终止。服务器主进程的主要任务是为每个客户端创建1个子进程 (这种实现方法的变体之一是为每个客户端创建1个线程)。

　　文件/etc/services包含大量服务，这表示系统理论上可以运行大量服务器进程，但其中大部分只是等待不频繁的连接请求或数据报。尽管如此，这些服务器进程还是被记录在内核进程表中，并占用了部分内存和交换空间。

　　守护进程inetd旨在避免运行大量不常用的服务器，它有2个主要优势：

　　● 无需为每个服务运行单独的守护进程，inetd会监控指定端口号并按需启动服务器。因此，系统中运行的进程数减少了。

　　● 由inetd启动的服务器的编程得到了简化，因为该守护进程会执行所有服务器启动时通常需要执行的一些步骤。

　　守护进程inetd负责管理大量服务，并按需启动服务器，所以它也称为互联网超级服务器守护进程。

　　守护进程inetd的行为由配置文件控制，该配置文件通常是/etc/inetd.conf。

　　某些Linux发行版还提供了inetd的扩展版xinetd。除了其他功能之外，xinetd添加了很多安全增强功能。

60.2 并发TCP echo服务器

　　TCP echo服务使用的端口号也是7。TCP echo服务器接受连接后一直循环，读取数据并将其通过同一套接字发回给客户端。服务器会一直读取，直到遇到EOF，然后关闭其套接字 (若客户端仍在读取，则它会遇到EOF)。

　　客户端可能发送任意字节数的数据给服务器，所以采用并发服务器设计是合适的，以便于多个客户端同时得到服务。

　　● 服务器的主体由for循环组成，每次循环会接受客户端连接，并通过fork()创建子进程，子进程会调用函数handleRequest()来服务客户端。同时，父进程会继续循环来接受下一个客户端连接。

　　● 通过fork()创建的子进程会继承父进程的监听套接字文件描述符和已连接的套接字文件描述符。只有子进程需要与客户端通信，所以父进程应该在fork()后立即关闭已连接的套接字文件描述符。同样，子进程不会接受新连接，所以它会关闭监听套接字文件描述符的副本。

　　● 所有子进程会在服务对应客户端后终止。

　　对于实际应用程序，可能需要为服务器可以创建的子进程数设置上限来防止攻击者发起远程fork炸弹 (通过该服务在系统中创建大量子进程使其无法正常使用)。为此，可以对运行中的子进程进行计数 (随着成功调用fork()和通过SIGCHLD处理函数回收进程而增减)。若达到上限，则临时停止接受连接 (或接受连接并立即关闭该连接)。

60.3 其他并发服务器设计

　　60.2的传统并发服务器设计足以满足很多需要通过TCP连接同时处理多个客户端的应用程序。但是，对于每分钟处理数千个请求的web服务器等负载很高的服务器，为每个客户端创建1个子进程带来的开销会给服务器带来沉重的负担，所以需要使用其他服务器设计。

60.3.1 预创建和预线程服务器

　　预创建和预线程服务器设计的核心思想如下：

　　● 服务器在启动后立即创建固定数量的子进程 (或线程)。这些子进程组成所谓的服务器池。

　　● 服务器池中的所有子进程每次服务1个客户端，并且这些子进程在服务完客户端后继续服务下一个待服务的客户端 (而非终止)。

　　服务器池应该足够大，以确保能够充分响应客户端请求。这表示服务器父进程需要监控空闲子进程数，并且在负载高峰期增加服务器池中的子进程数来确保始终有足够的子进程数立即为新客户端提供服务。若负载降低，则减少服务器池中的子进程数，因为多余的子进程会降低系统整体性能。

　　此外，服务器池中的子进程都必须遵循某种协议，以便能够独占地选择单个客户端连接。对于Linux和大多数UNIX实现，让服务器池中的每个子进程对监听套接字文件描述符调用accept()即可 (服务器父进程应在创建子进程之前创建监听套接字文件描述符，通过fork()创建的子进程会继承该文件描述符)。当新客户端连接到达时，只有1个子进程能够成功调用该系统调用。但是，对于某些旧实现，该系统调用是非原子的，所以应该通过某种互斥技术将该系统调用保护起来，以确保每次只有1个子进程调用该系统调用。

　　除了服务器池中的所有子进程都调用accept()之外，还有其他方法。若服务器池由进程组成，则服务器父进程可以调用accept()，然后将已连接的套接字文件描述符传递给服务器池中的某个空闲子进程。若服务器池由线程组成，则主线程可以调用accept()，然后将已连接的套接字文件描述符传递给服务器池中的某个空闲线程。

60.3.2 在单个进程中服务多个客户端

　　在某些情况下，需要设计单个服务器进程来服务多个客户端。为此，必须使用允许单个进程同时监控多个文件描述符的I/O事件的I/O模型 (I/O多路复用、信号驱动I/O或epoll)。

　　对于单进程服务器设计，服务器进程必须执行某些通常由内核处理的调度任务。对于单个服务器进程对应单个客户端的设计，内核可以确保每个服务器进程能公平地共享服务器的资源。但是，当使用单进程服务器来服务多个客户端时，服务器必须执行一些操作来避免某些客户端垄断对服务器的访问，而其他客户端无法得到服务的情况。

60.3.3 使用服务器群

　　处理高客户端负载的其他方法涉及使用由多个服务器组成的系统——服务器群。构建服务器群的最简单方法之一是采用DNS轮询负载共享 (或负载分配)，即某个区域的权威域名服务器将同一域名映射到多个IP地址。当向DNS服务器发送连续的域名请求时，返回的IP地址会以轮询方式按不同顺序呈现。

　　轮询DNS的优势是成本低且易于设置，但它会带来一些问题：

　　● 问题之一是远程DNS服务器会执行缓存，这表示来自客户端的针对特定主机 (或多个主机) 的未来请求会绕过轮询DNS服务器，并始终由同一服务器处理。此外，轮询DNS服务器没有内置机制来保证良好的负载均衡或高可用性。

　　● 另一个需要考虑的问题——这也是采用多台服务器的设计所面临的问题——确保服务器亲和性，即来自同一客户端的一系列请求会被定向到同一服务器，以便服务器维护的关于该客户端的任何状态信息保持准确。

　　更灵活但更复杂的解决方法是服务器负载均衡。对于这种场景，单个负载均衡服务器会将传入客户端连接路由到服务器群成员 (为了确保高可用性，可能会设置备用负载均衡服务器，以便在主负载均衡服务器崩溃时接管)。这避免了与远程DNS缓存的相关问题，因为服务器群对外仅呈现1个IP地址 (即负载均衡服务器的IP地址)。 负载均衡服务器采用算法来测量或估算负载 (可能基于服务器群成员提供的指标)，并智能地将负载分配到服务器群的各个成员。负载均衡服务器也会自动检测服务器群成员的故障 (并在必要时添加新服务器)。此外，负载均衡服务器还可以为服务器亲和性提供支持。

60.4 互联网超级服务器守护进程inetd

　　守护进程inetd通常在系统引导时被启动。为了成为守护进程，inetd会执行以下步骤：

　　1) 对于配置文件中指定的服务，inetd为其创建适当类型 (流或数据报) 的套接字并将其绑定到指定端口。对于TCP端口，inetd还会调用listen()将其转换为监听套接字。

　　2) 通过系统调用select()，inetd可以监控第1步中创建的套接字的数据报或传入连接请求。

　　3) select()会阻塞inetd，直到某个UDP套接字有数据报可读或某个TCP套接字收到连接请求。对于TCP连接，inetd会调用accept()接受请求。

　　4) 为了启动套接字对应的服务器程序，inetd会调用fork()创建子进程，子进程会调用exec()启动服务器程序。在调用exec()之前，子进程会关闭有数据报可读的UDP套接字文件描述符、监听套接字文件描述符或已连接的TCP套接字文件描述符以外的所有继承自父进程的文件描述符，然后将套接字文件描述符复制给文件描述符0~2并关闭套接字文件描述符 (可选地将服务器的用户和组ID设置为配置文件中指定的值)。

　　5) 若第3步中通过TCP套接字接受了连接，则inetd会关闭已连接的套接字文件描述符。

　　6) inetd回到第2步。

　　● 第2个字段是套接字类型，用于指定服务使用的套接字的类型 (例如，stream和dgram)。

　　● 第3个字段是协议，用于指定服务使用的套接字的协议。该字段的值取自文件/etc/protocols，但几乎所有服务都将给该字段指定为tcp或udp。inetd会使用服务名字段和协议字段的组合搜索文件/etc/services来确定应该为服务监控哪个端口。

　　● 第4个字段是标志，用于指定inetd启动的服务器是否临时接管对应服务的套接字。若该字段为wait，则服务器会临时接管套接字 (在服务器运行期间，inetd会从select()监控的文件描述符集中临时删除套接字文件描述符，inetd通过注册SIGCHLD处理函数来检测这一点)。若该字段为nowait，则服务器不会临时接管套接字。

　　● 第5个字段是登录名，即文件/etc/passwd中的用户名，其后可以加上句点.以及取自文件/etc/group的组名。该字段用于指定服务器运行时使用的用户和组ID (inetd运行时指定的有效用户ID是root，所以子进程也是特权进程，并且可以按需调用setuid()和setgid()来修改进程凭证)。

　　● 第6个字段是服务器程序名，即待执行的服务器程序的路径名。

　　● 第7个字段是服务器程序参数，由通过空格分隔的参数组成。该字段将作为运行程序时的参数列表。第1个参数对应argv[0]，所以通常是服务器程序名字段的基础部分。第2个参数对应argv[1]，以此类推。

　　示例中的服务ftp、telnet和login的服务器程序参数字段不同于这里的介绍，因为这些服务都会导致inetd调用TCP守护进程包装程序tcpd，该程序会在执行第1个参数指定的程序之前记录日志和执行访问控制检测。

　　由inetd调用的TCP服务器通常会被设计为仅处理1个客户端连接然后终止 (留下inetd负责监听更多连接的任务)。对于这种服务器，标志字段应该被指定为nowait。相反，若服务器负责接受连接，则应该将标志字段指定为wait。在这种情况下，inetd会将监听套接字文件描述符作为文件描述符0传递给服务器。

　　对于大多数UDP服务器，标志字段应该被指定为wait。由inetd调用的UDP服务器通常会被设计为读取并处理所有待读取的数据报，然后终止 (当读取套接字时，通常需要超时机制，以便指定时间内没数据报到达时服务器终止)。将标志字段指定为wait可以防止inetd试图通过select()监控套接字，进而导致与服务器竞争，并在竞争胜利的情况下再次创建服务器实例。

　　为了提高效率，inetd本身实现了几个简单服务 (例如，UDP和TCP echo服务)。对于这种服务，对应的配置文件条目的服务器程序字段被指定为internal，并且没有服务器程序参数字段。

　　1) 执行套接字相关初始化 (调用socket()、bind()和listen())。
