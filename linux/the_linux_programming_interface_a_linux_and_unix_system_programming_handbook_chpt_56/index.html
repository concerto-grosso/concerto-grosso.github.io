《Linux/UNIX系统编程手册》第56章 套接字：简介

发表于 2026-07-04 更新于 2026-07-05 分类于 Linux 本文字数： 5.2k

　　套接字是允许同一主机或通过网络连接的不同主机的应用程序交换数据的IPC方法。1983年，随着4.2BSD的发布，第1个广泛使用的套接字API出现，该API已被移植到几乎所有UNIX实现和大多数其他操作系统。

　　套接字接口在POSIX.1g中有正式规定，该标准作为草案标准约10年后，于2000年正式发布。该标准现已被SUSv3取代。

　　对于典型客户端-服务器场景，应用程序通过套接字通信，具体如下：

　　● 每个应用程序创建1个套接字。套接字是允许通信的 "装置"。这2个应用程序都需要1个套接字。

　　● 服务器将其套接字绑定到知名地址 (名称)，以便于客户端定位其套接字。

　　套接字由系统调用socket()创建，该系统调用会返回引用该套接字的文件描述符供后续调用使用。

　　套接字存在于通信域中。通信域决定了标识套接字的方法 (套接字地址的格式) 和通信范围 (同一主机的应用程序之间的通信还是通过网络连接的不同主机的应用程序之间的通信)。

　　现代操作系统至少支持UNIX域、IPv4域和IPv6域。

　　● UNIX域 (AF_UNIX) 允许同一主机的应用程序之间通信 (POSIX.1g使用了名称AF_LOCAL作为AF_UNIX的同义词，但SUSv3未说明该名称)。

　　● IPv4域 (AF_INET) 允许运行在通过网际协议第4版 (IPv4) 网络连接的不同主机的应用程序之间通信。

　　● IPv6域 (AF_INET6) 允许运行在通过网际协议第6版 (IPv6) 网络连接的不同主机的应用程序之间通信。

　　某些代码使用的常量名是PF_UNIX (而非AF_UNIX)。对于这种语境，AF表示地址族，而PF表示协议族。最初的想法是协议族可能支持多个地址族。实际上，迄今为止尚未定义过支持多个地址族的协议族，并且所有现有实现都将PF_常量定义为对应的AF_常量的同义词 (SUSv3说明了AF_常量，但没有说明PF_常量)。

　　所有套接字实现都至少提供了流套接字和数据报套接字。UNIX域和互联网域均支持这2种套接字类型。

　　流套接字提供了可靠的双向字节流通信通道。

　　● 可靠表示可以保证传输的数据要么会完整地到达接收端应用程序，与发送端传输的状态完全一致 (假设网络连接和接收端均未发生故障)，要么收到传输可能失败的通知。

　　● 双向表示数据可以在1对套接字之间双向传输。

　　● 字节流表示没有消息边界的概念 (如同无名管道)。

　　流套接字类似于使用2个无名管道来实现2个应用程序之间的双向通信，不同之处在于互联网域套接字允许通过网络进行通信。

　　流套接字是成对连接的，所以流套接字被称为面向连接的。术语对等套接字指连接另一端的套接字，对等地址指该套接字的地址，对等应用程序指使用该对等套接字的应用程序。有时，术语远程或外部与对端互为同义词。同样，术语本地指连接本端的应用程序、套接字或地址。1个流套接字只能与1个对端建立连接。

　　数据报套接字允许以数据报的消息形式交换数据。当使用数据报套接字时，消息边界得到保留，但数据传输并不可靠。消息可能乱序或重复到达，甚至根本无法送达。

　　数据报套接字是更通用的无连接套接字概念的例子之一。不同于流套接字，数据报套接字无需与另一个套接字连接即可使用。

　　对于互联网域，数据报套接字使用用户数据报协议 (UDP)，而流套接字通常使用传输控制协议 (TCP)。术语互联网数据报套接字和互联网流套接字很少使用，通常使用的术语是UDP套接字和TCP套接字。

　　主要套接字系统调用如下：

　　● 系统调用socket()会创建套接字。

　　● 系统调用bind()会将套接字绑定到地址。服务器通常会使用该系统调用来将其套接字绑定到知名 (固定) 地址，以便于客户端定位其套接字。

　　● 系统调用listen()允许流套接字接受来自其他套接字的传入连接。

　　● 系统调用accept()会接受监听流套接字的来自对等应用程序的连接，并可选地返回对等套接字的地址。

　　● 系统调用connect()会建立与另一个套接字的连接。

　　对于大多数Linux架构 (例外包括Alpha和IA-64)，以上所有套接字系统调用都被实现为库函数，并通过系统调用socketcall()进行多路复用 (这是由于Linux套接字实现最初作为独立项目开发时的产物)。尽管如此，本书还是将这些函数称为系统调用，因为在最初的BSD实现和很多同时期的UNIX实现中，它们就是如此。

　　套接字I/O可以通过传统I/O系统调用 (例如，write()和read()) 执行，也可以通过套接字专用系统调用 (例如，send()、recv()、sendto()和recvfrom()) 执行。在默认情况下，若I/O不能立即完成，则这些系统调用会阻塞进程。可以通过fcntl()的操作F_SETFL启用打开文件状态标志O_NONBLOCK来执行非阻塞I/O。

　　对于Linux，可以通过ioctl(fd, FIONREAD, &cnt)来获取文件描述符fd引用的流套接字中可读的未被读取的字节数。对于数据报套接字，该操作会返回下一个未被读取的数据报的字节数，若没有待处理的数据报，则返回0。SUSv3没有说明该特性。

　　对于互联网域套接字，服务器可以省略bind()调用，直接调用listen()，这样内核会为该套接字选择临时端口。随后，服务器可以通过getsockname()获取其套接字的地址。对于这种情况，服务器必须发布该地址，以便客户端定位其套接字 (这种发布可以通过将服务器地址注册到集中式目录服务应用程序来实现，客户端随后通过该应用程序获取服务器地址。当然，集中式目录服务应用程序的套接字必须绑定到知名地址)。

56.1 socket()

　　系统调用socket()会创建套接字。参数domain用于指定套接字通信域。参数type用于指定套接字类型，该参数通常被指定为SOCK_STREAM (流套接字) 和SOCK_DGRAM (数据报套接字)。

　　对于本书介绍的套接字类型，参数protocol总是被指定为0 (例如，对于原始套接字SOCK_RAW，该参数应该被指定为IPPROTO_RAW)。

　　socket()会在成功时返回引用创建的套接字的文件描述符。

　　从内核2.6.27开始，Linux提供了参数type的第2种用法：允许将其指定为2个非标准标志与套接字类型进行或运算|的结果。这2个非标准标志如下：

　　● 标志SOCK_CLOEXEC会启用套接字文件描述符的close-on-exec标志。

　　● 标志SOCK_NONBLOCK会启用底层打开的文件描述的标志O_NONBLOCK (后续的I/O操作会以非阻塞模式执行)。

56.2 bind()

　　系统调用bind()会将文件描述符sockfd引用的套接字绑定到参数addr指向的地址结构体。该结构体的类型取决于套接字域，其大小由参数addrlen指定 (SUSv3详细说明了其类型socklen_t)。

　　结构体sockaddr作为所有域特有的地址结构体的模板。所有地址结构体的第1个成员都是family，该成员对应结构体sockaddr的成员sa_family (SUSv3详细说明了其类型sa_family_t)。成员family的值足以确定存储在该结构体剩余部分的地址的大小和格式。

　　某些UNIX实现还定义了结构体sockaddr的额外成员sa_len，用于指定该结构体的总大小。SUSv3并不要求实现提供该成员，并且Linux的套接字API实现也没有提供该成员。

　　若定义了特性测试宏_GNU_SOURCE，则glibc会在头文件sys/socket.h中使用gcc扩展来声明各个套接字系统调用的函数原型，从而无需进行(struct sockaddr *)类型转换。但是，依赖该特性会导致程序无法移植，因为这会在其他系统上引发编译警告。

56.3 流套接字

　　流套接字通常分为主动套接字和被动套接字。

　　● 通过socket()创建的套接字默认为主动套接字。可以在connect()调用中指定主动套接字来建立与被动套接字的连接，这种方式称为执行主动打开。

　　● listen()会将套接字标记为允许接受传入连接，这种套接字是被动套接字。接受传入连接称为执行被动打开。

　　对于大多数使用流套接字的应用程序，服务器会执行被动打开，而客户端会执行主动打开 (后续的内容会默认这种场景)。

　　关闭套接字的常用方法是调用close()。若多个文件描述符引用同一套接字，则当所有文件描述符都被关闭后，连接才会被关闭。系统调用shutdown()提供了如何关闭流套接字连接的更精细的控制。

56.3.1 listen()

　　系统调用listen()会标记文件描述符sockfd引用的流套接字，该套接字后续可用于接受来自主动套接字的连接。

　　无法对已连接的套接字 (成功调用connect()的套接字或accept()返回的套接字) 调用listen()。

　　当服务器忙于处理某些客户端时，可能导致其他客户端的连接成为待处理连接。

　　内核必须记录所有待处理连接请求的某些信息，以便后续的accept()调用可以处理它们。参数backlog可用于指定这些待处理连接请求的上限数。在该限制范围内的连接请求会立即完成。超过该限制的连接请求会被阻塞，直到待处理连接请求被接受，然后从待处理连接队列中被删除。

　　SUSv3允许实现为backlog的值设置上限并静默地将其值向下调整至上限值。SUSv3规定，实现应将该限制定义为头文件sys/socket.h中的常量SOMAXCONN。对于Linux，该常量的值为128。但是，从内核2.4.25开始，Linux允许通过Linux特有的文件/proc/sys/net/core/somaxconn来修改该限制 (对于早期内核版本，限制SOMAXCONN是不可修改的)。

　　对于最初的BSD套接字实现，backlog的上限是5。所有现代实现允许更大的backlog上限。

56.3.2 accept()

　　系统调用accept()会接受文件描述符sockfd引用的监听套接字上的传入连接。若没有待处理连接，则该系统调用会阻塞进程，直到连接请求到达。

　　accept()会创建新套接字，而这个新套接字已与调用connect()的对等套接字建立连接。新套接字的文件描述符会作为accept()调用的结果返回。监听套接字会保持打开状态，可用于接受后续连接。

　　accept()的剩余参数用于返回对等套接字的地址。

　　● 参数addr指向用于返回套接字地址的结构体，该参数的类型取决于套接字域。

　　● 参数addrlen是值-结果参数。在调用accept()之前，该参数用于指定addr指向的缓冲区的大小。在调用accept()之后，该参数会被设置为实际复制到addr指向的缓冲区中的字节数。

　　当不需要使用对等套接字的地址时，可以将addr和addrlen都指定为NULL。

　　从内核2.6.28开始，Linux提供了非标准系统调用accept4()。它与accept()执行相同的任务，但支持额外的参数flags，该参数可用于控制该系统调用的行为。flags支持标志SOCK_CLOEXEC和SOCK_NONBLOCK。前者会启用accept4()返回的文件描述符的close-on-exec标志，后者会启用底层打开的文件描述的标志O_NONBLOCK。

56.3.3 connect()

　　系统调用connect()会将文件描述符sockfd引用的主动套接字连接到参数addr和addrlen指定的地址。

　　参数addr和addrlen的指定方式与对应的bind()参数相同。

　　当connect()出错后需要再次尝试连接时，SUSv3规定，可移植的实现方法是关闭该套接字，创建新套接字并使用新套接字重新尝试连接。

56.3.4 流套接字I/O

　　已连接的套接字的I/O语义在以下方面与无名管道类似：

　　● 为了执行I/O，需要使用read()和write()或套接字专用的send()和recv()。因为套接字是双向的，所以连接的两端都可能调用这些系统调用。

　　● 套接字可以通过close()关闭或在应用程序终止时自动被关闭。随后，当对等应用程序读取其套接字时，会得到EOF (一旦所有缓冲的数据都被读取)。若对等应用程序试图写入其套接字，则它会收到信号SIGPIPE，而系统调用会导致错误EPIPE (处理这种情况的方法通常是忽略信号SIGPIPE并根据错误EPIPE来确定连接是否关闭)。

56.4 数据报套接字

　　当从某个地址发送多个数据报到其他地址时，无法保证它们会按发送顺序到达，甚至无法保证它们一定能到达。由于底层网络协议有时会重传数据报，所以同一数据报可能多次到达。

56.4.1 recvfrom()和sendto()

　　系统调用recvfrom()和sendto()可用于在数据报套接字上接收和发送数据报。

　　这2个系统调用的返回值和前3个参数与read()和write()的相同。第4个参数flags是位掩码，用于控制套接字特有的I/O特性。若不需要使用这些特性，则可以将该参数指定为0。最后2个参数用于获取或指定对等套接字的地址。

　　对于recvfrom()，参数src_addr和addrlen会返回用于发送数据报的对等套接字的地址。src_addr是指向与通信域对应的地址结构体的指针。addrlen是值-结果参数 (调用recvfrom()前应该将该参数设置为src_addr指向的结构体的大小，返回时该参数会被设置为实际写入该结构体的字节数)。

　　当不需要使用发送端套接字的地址时，可以将src_addr和addrlen都指定为NULL。此时，recvfrom()等同于recv()。此外，可以通过read()读取数据报，等同于调用recv()并将flags指定为0。

　　无论将length指定为多少，recvfrom()都只会读取1条消息。若该消息的长度超过length字节，则该消息会被静默地截断为length字节。

　　对于sendto()，参数dest_addr和addrlen用于指定发送数据报的目标地址。dest_addr是指向与通信域对应的地址结构体的指针，它会被初始化为目标套接字的地址，其大小由addrlen指定。

　　对于Linux，可以通过sendto()发送长度为0的数据报。但是，并非所有UNIX实现都允许这样做。

56.4.2 在数据报套接字中使用connect()

　　尽管数据报套接字是无连接的，但对数据报套接字调用connect()仍然有用。这会让内核将特定地址记录为该套接字的对端。这种套接字称为已连接的数据报套接字。未调用connect()的数据报套接字称为未连接的数据报套接字。

　　当连接数据报套接字后，数据报可以通过write() (或send()) 发送，并且会自动到达同一对等套接字。与通过sendto()一样，每次调用write()会生成单独的数据报。该套接字只能用于读取由对等套接字发送的数据报。

　　connect()对于数据报套接字的作用是非对称的。上述说明仅适用于调用connect()的套接字，而不适用于它所连接的对等套接字 (除非对等应用程序对其套接字调用connect())。

　　可以通过再次调用connect()来修改已连接的数据报套接字的对端。此外，还可以指定地址族为AF_UNSPEC的地址结构体来解除与对端的关联，但很多UNIX实现不支持将AF_UNSPEC用于该目的。SUSv3对解除对端连接的处理说明比较模糊，仅说明可以调用connect()并指定 "空地址" 来重置连接，并未对该术语进行定义。SUSv4则明确规定应使用AF_UNSPEC。

　　为数据报套接字设置对端的显著优势在于，通过套接字传输数据时可以使用更简单的I/O系统调用 (无需使用sendto()，可以直接使用write())。设置对端对向单个对端发送多个数据报的应用程序很有用。

　　对于某些TCP/IP实现，将数据报套接字连接到对端可以提高性能。但是，对于Linux，连接数据报套接字对性能几乎没有影响。
