　　当通过bind()绑定UNIX域套接字时，该系统调用会在文件系统中创建1个文件 (套接字路径名中的目录必须是可访问和可写入的)。该文件的所有权根据文件创建的常规规则确定，并且会被标记为套接字。当对该路径名调用stat()时，结果结构体stat的成员st_mode的文件类型部分会包含S_IFSOCK。当使用命令ls -l时，UNIX域套接字的第1列会显示为s，而命令ls -F的结果中UNIX域套接字路径名的结尾附上等号=。

　　尽管UNIX域套接字由路径名标识，但对它执行的I/O不涉及对底层设备的操作。

　　关于绑定UNIX域套接字，以下几点值得注意：

　　● 无法将套接字绑定到现有路径名 (bind()会导致错误EADDRINUSE)。

　　● 通常会将套接字绑定到绝对路径名，这样套接字就会位于文件系统的固定地址。此外，可以将套接字绑定到相对路径名，但这不常见，因为这需要调用connect()的应用程序知道调用bind()的应用程序的当前工作目录。

　　● 1个套接字只能绑定到1个路径名，而1个路径名也只能被绑定到1个套接字。

　　● 无法使用open()来打开套接字。

　　● 当不再需要套接字时，通常应该通过unlink()或remove()删除该套接字绑定的路径名。

　　本书的大多数示例都会将UNIX域套接字绑定到目录/tmp下的路径名，因为该目录在所有系统中通常都存在并且可写。实际应用程序应该将UNIX域套接字绑定到安全目录下的路径名。

　　UNIX域套接字文件的所有权和权限决定哪个进程能够与该套接字通信：

　　● 连接UNIX域流套接字需要套接字文件的写入权限和套接字路径名中的所有目录的执行权限。

　　● 发送数据报给UNIX域数据报套接字需要套接字文件的写入权限和套接字路径名中的所有目录的执行权限。

　　在默认情况下，当 (通过bind()) 创建套接字时，其所有权限都会授予给所有者 (用户)、组和其他。为了修改这些权限，需要在创建套接字之前调用umask()来禁用不需要授予的权限。

　　有些系统会忽略套接字文件的权限 (SUSv3允许这样做)。因此，无法以可移植的方式使用套接字文件权限来控制对套接字的访问 (尽管可以通过套接字文件所在目录的权限来实现该目的)。

57.2 UNIX域数据报套接字

　　如前所述，使用数据报套接字进行通信是不可靠的。这适用于通过网络传输的数据报。但是，对于UNIX域套接字，数据报的传输是在内核内进行的，所以是可靠的。所有消息都会按顺序传递且不会重复。

　　SUSv3没有规定通过UNIX域套接字发送的数据报的最大大小。Linux允许发送相当大的数据报 (数据报大小限制由套接字选项SO_SNDBUF和各种/proc文件控制)，但有些UNIX实现的限制较小 (例如，2048字节)。使用UNIX域数据报套接字的可移植应用程序应考虑较小的数据报大小限制。

57.3 socketpair()

　　系统调用socketpair()会创建1对套接字并将它们连接，引用它们的文件描述符会被存储在数组sockfd中。

　　该系统调用仅适用于UNIX域，所以参数domain必须被指定为AF_UNIX (该限制适用于大多数实现)。参数type必须被指定为SOCK_DGRAM或SOCK_STREAM。参数protocol必须被指定为0。

　　将type指定为SOCK_STREAM会创建等同于双向无名管道的套接字对。每个套接字都可用于读取和写入，并且2个套接字之间的每个方向有独立的双向数据管道 (对于BSD衍生实现，pipe()是基于socketpair()实现的)。

　　通常，套接字对的用法类似于无名管道。调用socketpair()后进程通过fork()创建子进程，子进程会继承父进程的文件描述符 (包括引用套接字对的文件描述符)。因此，父子进程可以通过该套接字对进行IPC。

　　socketpair()与手动创建1对套接字并连接的区别在于，套接字未绑定到任何地址。这有助于避免某些安全漏洞，因为套接字对其他任何进程不可见。

　　从内核2.6.27开始，Linux提供了参数type的第2种用法：允许将其指定为2个非标准标志与套接字类型进行或运算|的结果。这2个非标准标志如下：

　　● 标志SOCK_CLOEXEC会启用套接字文件描述符的close-on-exec标志。

　　● 标志SOCK_NONBLOCK会启用底层打开的文件描述的标志O_NONBLOCK (后续的I/O操作会以非阻塞模式执行)。

57.4 Linux抽象套接字命名空间

　　Linux特有特性抽象命名空间允许将UNIX域套接字绑定到1个名称，而无需在文件系统中创建该名称。这提供了一些潜在优势：

　　● 绑定套接字的名称不会与文件系统中的现有名称冲突。

　　● 当不再需要套接字时，无需取消链接套接字路径名。抽象名会在套接字关闭时自动被删除。

　　● 无需为套接字创建文件系统路径名。当位于chroot环境或没有文件系统写入权限时，这很有用。

　　创建抽象绑定需要将成员sun_path的第1个字节指定为null字节 (字符\0)。这会将抽象套接字名与传统UNIX域套接字路径名区分开来，传统路径名由若干个非null字节组成并以null字节结尾。sun_path的剩余字节定义了套接字的抽象名 (这些字节会被完整地解释)。
