《Linux/UNIX系统编程手册》第59章 套接字：互联网域

发表于 2026-08-15 更新于 2026-08-19 分类于 Linux 本文字数： 13k

　　互联网域流套接字被实现为基于TCP，它提供了可靠的双向字节流通信通道。

　　互联网域数据报套接字被实现为基于UDP，它类似于UNIX域数据报套接字，但两者存在以下不同：

　　● UNIX域数据报套接字是可靠的，但UDP套接字不是可靠的 (数据报可能乱序、重复或丢失)。

　　● 若接收套接字的数据队列已满，则通过UNIX域数据报套接字发送数据会阻塞进程。相比之下，当使用UDP套接字时，若传入数据会导致接收端的数据队列溢出，则该数据报被静默丢弃。

　　不同硬件架构存储多字节整数的顺序可能不同，这种字节顺序分为2类：大端和小端 (这些术语源于Jonathan Swift 1726年的讽刺小说《格列佛游记》，书中这些术语指代在煮熟的鸡蛋的两端打开的对立政治派别)，前者将最高有效字节存储在最低内存地址，而后者将最低有效字节存储在最低内存地址。x86和Digital的VAX架构使用的是小端模式，而大多数其他架构都是使用大端模式。有些硬件架构可以在这2种模式之间切换。特定机器的字节顺序称为主机字节顺序。

　　主机名是连接到网络的系统的符号标识符。服务名是端口号的符号表示。

　　● 主机地址可以通过二进制值、符号主机名或表示格式 (点分十进制IPv4地址或十六进制IPv6地址) 表示。

　　● 端口可以通过二进制值或符号名表示。

　　当编写通过网络通信的应用程序时，必须使用互联网域套接字。当使用套接字在同一系统上的应用程序之间通信时，仅使用互联网域套接字通常是最简单的方法，因为它既可以在单台主机上运行，也能在通过网络连接的不同主机上运行。但是，在这种情况下，相比互联网域套接字，UNIX域套接字存在以下优势：

　　● 对于某些实现，UNIX域套接字比互联网域套接字更快。

　　● 可以通过目录权限来控制对UNIX域套接字的访问，这样只有具有指定用户ID (或组ID) 的应用程序才能连接监听套接字或向数据报套接字发送数据报。这提供了简单的客户端身份验证方法。对于互联网域套接字，若需要对客户端进行身份验证，则需要做更多工作。

　　● 使用UNIX域套接字，可以传递打开的文件描述符或发送者凭证。

59.1 网络字节顺序

　　IP地址和端口号都是整数值，它们必须在网络的不同主机之间传输并被理解，所以必须使用标准字节顺序，该字节顺序称为网络字节顺序，并且是大端模式。

59.2 数据表示

　　当开发网络程序时，需要注意不同计算机架构在表示各种数据类型时采用的约定不同 (例如，C的长整型在某些系统上是32位，而在其他系统上是64位。对于结构体，情况则更复杂，不同实现会使用不同的规则来将结构体成员对齐到主机系统的地址边界，这会导致成员之间的填充字节数不同)。

　　由于数据表示之间的不同，通过网络在异构系统之间交换数据的应用程序必须采用某种通用的编码约定。发送端必须按照这种约定来编码数据，而接收端必须按照同一约定来解码。将数据转化为标准格式以便通过网络传输的过程称为编组。

　　目前存在多种编组标准，包括外部数据表示法 (XDR，见RFC 1014)、抽象语法标记1 (ASN.1) 的基本编码规则 (BER)、CORBA和XML。这些标准通常会为每种数据类型定义固定格式 (包括字节顺序和使用的位数)。除了通过所需格式编码之外，每个数据项带有标识其类型的额外字段 (可能还带有长度字段)。

　　但是，通常使用的编组方法是将所有待传输的数据编码为文本格式，其中的各个数据项由指定的字符分隔 (通常是换行符)。这种方法的优点是可以通过telnet来调试应用程序：

　　函数readLine()一直会从文件描述符fd引用的文件中读取字节，直到遇到换行符。读取的字节会被存储在参数buffer指向的缓冲区中，其大小至少为n字节。读取的字符串总是以\0结尾。一旦成功，该函数会返回存储在buffer指向的缓冲区的字节数 (最多n - 1)，结尾的\0不会计入其中。

　　若在遇到换行符之前读取的字节数不小于n - 1，则readLine()会丢弃剩余字节 (包括换行符)。因此，可以通过buffer指向的缓冲区中是否包含换行符来确定是否有字节被丢弃。这种处理方法是为了避免那些依赖按行处理输入的应用程序协议将1行很长的内容作为多行来处理 (否则，两端应用程序失去同步很可能导致协议失效)。或者，让readLine()仅读取足以填满缓冲区的字节数，将剩余字节 (直至下一个换行符) 留给下一次调用readLine()处理。对于这种情况，readLine()的调用者需要处理部分读取的情况。

59.4 inet_pton()和inet_ntop()

　　函数inet_pton()和inet_ntop()可用于IPv4和IPv6地址与二进制形式和点分十进制/十六进制字符串表示法之间的转换。函数名中的n和p分别表示network和presentation。表示形式是人类可读的字符串，包括以下形式：

　　● 点分十进制IPv4地址 (204.152.189.116)

　　● 以冒号分隔的十六进制IPv6地址 (::1)

　　● IPv4映射IPv6地址 (::FFFF:204.152.189.116)

　　inet_pton()会将表示字符串src转换为网络字节顺序的二进制IP地址。参数domain应该被指定为AF_INET或AF_INET6。转换结果会被存储在参数addrptr指向的结构体in_addr或in6_addr中。

　　inet_ntop()会将参数addrptr应该指向待转换的结构体in_addr或in6_addr转换为地址字符串。参数domain应该被指定为AF_INET或AF_INET6。结果字符串 (以\0结尾) 会被存储在dst_str指向的缓冲区中，其大小由参数len指定。若len太小，则inet_ntop()会返回NULL，并将errno设置为ENOSPC。

59.6 DNS

　　在DNS诞生之前，主机名和IP地址之间的映射是通过手动维护本地文件/etc/hosts定义的，该文件包含以下形式的记录：

　　函数getaddrinfo()的前身gethostbyname()通过搜索该文件来获取IP地址，查找与规范主机名 (即主机的官方名称或主要名称) 或 (可选的以空格分隔的) 别名匹配的记录之一。

　　但是，/etc/hosts方案的可扩展性很差。当网络包含数百万台主机时，该方案将变得不可行。DNS的设计初衷就是为了解决这个问题，其核心思想如下：

　　● 主机名被组织为层次命名空间。DNS层次结构的每个节点有1个标签 (名称)，其长度最长为63个字符。该层次结构的根节点是未命名的节点，即匿名根。

　　● 节点的域名由该节点及其所有根节点的名称连接而成，这些名称由句点.分隔 (例如，节点google的域名是google.com)。

　　● www.kernel.org.等完全限定域名 (FQDN) 用于标识DNS层次结构中的主机。FQDN以句点结尾，但该句点通常可以被省略。

　　● 整个DNS层次结构并非由单个组织或系统管理。相反，DNS服务器构成1个层次结构，每个服务器管理树的对应的分支 (区域)。通常，每个区域有1个主域名服务器和若干个从域名服务器 (也称为辅域名服务器)，从域名服务器用于在主域名服务器崩溃时提供备份。区域本身可以细分为单独管理的更小区域。当在区域内添加主机或更改主机名到IP地址的映射关系时，负责对应本地域名服务器的管理员需要更新其服务器上的域名数据库 (层次结构中的其他域名服务器数据库均无需手动修改)。

　　● 当程序调用getaddrinfo()来解析域名时，该函数会通过库函数 (resolver库) 来与本地DNS服务器通信。若该DNS服务器无法提供所需信息，则该函数会与DNS服务器层次结构中的其他DNS服务器通信来获取信息。解析过程有时可能消耗大量时间，并且DNS服务器使用缓存机制来避免与经常访问的域名进行不必要的通信。

　　采用以上方法可以让DNS处理大型命名空间，并且不需要集中管理域名。

　　Linux使用的DNS服务器实现是广泛使用的Berkeley Internet Name Domain (BIND) 实现named，该实现由互联网系统联盟 (ISC) 维护。该守护进程的行为由文件/etc/named.conf控制。

59.6.1 迭代和递归解析请求

　　DNS解析请求分为递归请求和迭代请求。对于递归请求，请求者会请求DNS服务器处理整个解析任务，包括必要时与任何其他DNS服务器通信的任务。当本地主机的应用程序调用getaddrinfo()时，该函数会向本地DNS服务器发起递归请求。若本地DNS服务器本身没有执行解析所需的信息，它将迭代地解析域名。

　　这里将通过1个示例来解释迭代解析。假设本地DNS服务器收到解析域名www.otago.ac.nz的请求。为此，它会先与少数几个所有DNS服务器都必须知道的根域名服务器通信，这些根服务器可以通过命令dig . NS获取。对于域名www.otago.ac.nz，根服务器会将本地DNS服务器指向某个nz DNS服务器。本地DNS服务器随后使用该域名查询nz DNS服务器，并收到指向ac.nz DNS服务器的响应。本地DNS服务器接着使用该域名查询ac.nz DNS服务器，并被指向otago.ac.nz DNS服务器。最后，本地服务器使用该域名查询otago.ac.nz DNS服务器，并得到所需的IP地址。

　　若提供给函数gethostbyname()的域名不完整，则解析器会在解析之前尝试补全域名。域名补全规则被定义在文件/etc/resolv.conf中。在默认情况下，解析器至少会尝试使用本地主机的域名进行补全 (例如，当登录到机器oghma.otago.ac.nz并输入命令ssh octavo时，生成的DNS查询将针对域名octavo.otago.ac.nz)。

59.8 协议无关的主机与服务转换

　　函数getaddrinfo()会将主机名和服务名转换为IP地址和端口号。

　　函数getnameinfo()执行与getaddrinfo()相反的任务，它会将 (IPv4和IPv6) 套接字结构体转换为包含对应主机名和服务名的字符串。

59.8.1 getaddrinfo()

　　给定1个主机名和1个服务名，getaddrinfo()会返回套接字结构体列表，其中的所有元素都包含1个IP地址和1个端口号。

　　参数host、service和hints作为getaddrinfo()的输入。host是主机名或数字地址字符串 (点分十进制IPv4地址或十六进制IPv6地址)。service是服务名或十进制端口号。hints指向结构体addrinfo，用于指定通过参数result返回的套接字地址结构体的更多选择标准。

　　作为输出，getaddrinfo()会动态分配由结构体addrinfo组成的链表，并将参数result设置为指向该链表的第1个元素。该链表的所有元素都包含1个与host和service对应的套接字地址结构体的指针。

59.8.1.1 参数result

　　getaddrinfo()会通过参数result返回结构体链表，而非单个结构体，因为对于host、service和hints中指定的条件，可能存在多种主机和服务的组合 (例如，对于具有多个网络接口的主机，可能会返回多个地址结构体)。此外，当hints.ai_socktype为0时，若给定服务同时支持UDP和TCP，则可能会返回2个结构体，分别用于TCP套接字和UDP套接字。

　　result返回的链表的每个元素描述了对应套接字地址结构体的属性。

　　● 成员ai_family表示套接字地址结构体的类型 (AF_INET或AF_INET6)。

　　● 成员ai_socktype表示套接字地址结构体是用于UDP服务还是TCP服务 (SOCK_STREAM或SOCK_DGRAM)。

　　● 成员ai_protocol表示套接字地址结构体的协议。

　　● 成员ai_addrlen表示ai_addr指向的套接字地址结构体的字节数。

　　● 成员ai_addr指向套接字结构体 (用于IPv4的结构体in_addr或用于IPv6的结构体in6_addr)。

　　● 成员ai_flags未被使用 (hints会使用该成员)。

　　● 成员ai_canonname仅用于第1个套接字地址结构体 (需要在hints.a_flags中指定了标志AI_CANONNAME)。

　　与gethostbyname()相同，getaddrinfo()可能会向DNS服务器发送请求 (该请求可能比较耗时)。

59.8.1.2 参数hints

　　当使用参数hints时，只会使用其成员ai_flags、ai_family、ai_socktype和ai_protocol，其他成员应该被设置为0或NULL。

　　hints.ai_family用于选择返回的套接字地址结构体的域。该成员可以被指定为AF_INET或AF_INET6 (或者其他实现支持的常量)。若需要获取所有类型的套接字地址结构体，则可以将该成员指定为AF_UNSPEC。

　　hints.ai_socktype用于选择返回的套接字地址结构体所使用的套接字类型。若该成员为SOCK_DGRAM，则会查找UDP服务 (并通过result返回对应的套接字地址结构体)。若该成员为SOCK_STREAM，则会查找TCP服务。若该成员为0，则查找所有类型的套接字。

　　hints.ai_protocol用于选择返回的套接字地址结构体的协议。若该成员为0，则表示选择所有协议。

　　hints.ai_flags是用于控制getaddrinfo()行为的位掩码，可以包含以下标志中的任意个 (或运算|)：

　　● 标志AI_ADDRCONFIG表示当且仅当本地系统配置了环回地址之外的IPv4或IPv6地址时，才会返回IPv4或IPv6地址。

　　● 标志AI_CANONNAME表示host不为NULL时返回以\0结尾的主机官方名字符串。该字符串会作为result指向的第1个结构体addrinfo的成员ai_canonname。

　　● 标志AI_NUMERICHOST表示将host解释为数字地址字符串。该标志可用于防止域名解析。

　　● 标志AI_NUMERICSERV表示将service解释为端口号。该标志可用于防止将服务名转换为端口号。

　　● 标志AI_PASSIVE表示返回被动套接字地址结构体。在这种情况下，host应该被指定为NULL，并且返回的套接字地址结构体的IP地址成员会被设置为通配IP地址。若未指定该标志，则返回主动套接字地址结构体。若未指定该标志，并且host为NULL，则返回的套接字地址结构体的IP地址成员会被设置为环回IP地址。

　　● 标志AI_V4MAPPED表示当hints.ai_family被指定为AF_INET6时，若不存在匹配的IPv6地址，则返回IPv4映射IPv6地址结构体。若同时指定了标志AI_ALL和AI_V4MAPPED，则会返回IPv6和IPv4映射IPv6地址结构体。

　　除了host之外，service也能被指定为NULL，这会导致返回的地址结构体的端口号被设置为0。但是，无法将host和service都指定为NULL。

　　若不需要以上选择标准，则可以将hints指定为NULL。在这种情况下，ai_socktype和ai_protocol会被假定为0，ai_flags会被假定为(AI_V4MAPPED | AI_ADDRCONFIG)，ai_family会被假定为AF_UNSPEC (glibc实现故意偏离了SUSv3，SUSv3要求ai_flags在这种情况下应该被假定为0)。

59.8.2 freeaddrinfo()

　　函数freeaddrinfo()会释放getaddrinfo()为通过result返回的结构体链表动态分配的内存。

59.8.4 getnameinfo()

　　getnameinfo()会执行与getaddrinfo()相反的任务。给定套接字地址结构体，该函数会返回对应的主机名和服务名字符串，若无法解析域名或服务名，则返回对应的IP地址或端口。

　　参数addr指向待转换的套接字地址结构体，其大小由参数addrlen指定。通常，这2个参数的值都是通过调用accept()、recvfrom()、getsockname()或getpeername()获取。

　　结果主机名和服务名字符串会被存储在参数host和service指向的缓冲区 (由调用者分配) 中，其大小需要通过参数hostlen和servlen传递。

　　头文件netdb.h定义了常量NI_MAXHOST和NI_MAXSERV来帮助host和service指向的缓冲区的大小。前者表示结果主机名字符串的最大字节数，其值为1025。后者表示结果服务名的最大字节数，其值为32。SUSv3没有说明这2个常量，但所有提供了getnameinfo()的UNIX实现都定义了它们 (对于glibc 2.8或更高版本，需要定义特性测试宏_BSD_SOURCE、_SVID_SOURCE或_GNU_SOURCE才能获取它们的定义)。

　　当不需要主机名时，可以将host和hostlen指定为NULL和0。当不需要主机名时，可以将service和servlen指定为NULL和0。但是，host和service不能都为NULL (对应的长度参数也不能都为0)。

　　参数flags是用于控制getnameinfo()的行为的位掩码，可以包含以下标志中的若干个 (或运算|)：

　　● 标志NI_DGRAM表示返回UDP套接字的主机名和服务名。在默认情况下，getnameinfo()返回的是TCP套接字的主机名和服务名。

　　● 标志NI_NAMEREQD表示无法解析域名时返回EAI_NONAME。在默认情况下，getnameinfo()会在无法解析主机名时通过host返回数字地址字符串。

　　● 标志NI_NOFQDN表示仅返回主机的FQDN的主机名部分。在默认情况下，getnameinfo()返回的是FQDN。

　　● 标志NI_NUMERICHOST表示通过host返回数字地址字符串。该标志可用于跳过域名解析。

　　● 标志NI_NUMERICSERV表示通过service返回十进制端口号。该标志可用于跳过搜索文件/etc/services。

　　getnameinfo()会在成功时返回0，出错时返回59.8.3的表格中的错误常量。

59.11 用于主机和服务转换的过时API

　　函数inet_aton()和inet_ntoa()可用于在点分十进制表示法和二进制形式 (网络字节顺序) 之间转换IPv4地址，它们现已被inet_pton()和inet_ntop()取代。

　　函数gethostbyname()和gethostbyaddr()可用于主机名和IP地址的相互转换，它们现已被getaddrinfo()和getnameinfo()取代。

　　函数getservbyname()和getservbyport()会从文件/etc/services检索记录，它们现已被getaddrinfo()和getnameinfo()取代。

59.11.1 inet_aton()和inet_ntoa()

　　inet_aton() (ASCII to network) 会将地址字符串str转换为网络字节顺序的IPv4地址，结果会被存储在参数addr指向的结构体中。若转换成功，则返回1；若str无效，则返回0。str可以不是十进制。该字符串可以是以0开头的八进制或者以0x和0X的开头的十六进制值。此外，该字符串支持简写模式，允许使用少于4个数字组件来指定地址。术语数字点分表示法表示采用该特征的更通用的地址字符串。

　　SUSv3未说明inet_aton()，但大多数实现都提供了该函数。对于Linux，当定义了特性测试宏_BSD_SOURCE、_SVID_SOURCE或_GNU_SOURCE后，该函数的声明会出现在头文件arpa/inet.h中。

　　inet_ntoa() (network to ASCII) 会执行与inet_aton()相反的任务。给定结构体in_addr (网络字节顺序的32位IPv4地址)，该函数会返回静态分配的点分十进制IPv4地址字符串 (再次调用该函数会覆盖该字符串)。

59.11.2 gethostbyname()和gethostbyaddr()

　　gethostbyname()会解析主机名name并返回指向静态分配的包含相关信息的结构体hostent的指针。

　　成员h_name是主机的官方名字符串。成员h_aliases是由主机名的别名字符串组成的数组。

　　成员h_addr_list是由主机的IP地址字符串组成的数组 (多宿主主机可能有多个IP地址)，其元素可以指向结构体in_addr或in6_addr。成员h_addrtype表示结构体的地址类型，其值为AF_INET或AF_INET6。成员h_length表示该数组的总大小。

　　定义宏h_addr是为了与4.2BSD等早期实现兼容，这些实现仅通过hostent返回1个地址。某些现有代码依赖于该名称。

　　对于gethostbyname()的现代版本，name可以被指定为数字IP地址字符串 (点分十进制IPv4地址或十六进制IPv6地址)。在这种情况下，该函数不会进行域名解析，name会被复制给结构体hostent的成员h_name，而成员h_addr_list会被设置为name对应的IP地址结构体。

　　gethostbyaddr()执行与gethostbyname()相反的任务。给定IP地址结构体，该函数会返回包含该地址的主机相关信息的结构体hostent。

　　一旦出错，gethostbyname()和gethostbyaddr()会返回NULL，并设置全局变量h_errno。顾名思义，该变量类似于errno，而函数herror()和hstrerror()类似于perror()和strerror()。

　　herror()会在标准错误打印字符串str加冒号:加h_errno中当前错误的消息。hstrerror()可用于获取参数err指定的错误对应的字符串。
