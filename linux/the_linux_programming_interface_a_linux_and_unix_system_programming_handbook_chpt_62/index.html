《Linux/UNIX系统编程手册》第62章 终端

发表于 2026-09-28 更新于 2026-09-30 分类于 Linux 本文字数： 14k

　　从历史角度，用户使用通过串口线 (RS-232) 连接的终端访问UNIX系统，这种终端是能够显示字符和简单图像的阴极射线管 (CRT)。通常，CRT提供了24行80列的单色显示。按照如今的标准，当时的CRT体积小且价格昂贵。在更早的时候，终端有时是纸质电传打字机。串口线用于将其他设备 (例如，打印机和调制解调器) 连接到计算机，或者连接2台计算机。

　　对于早期UNIX系统，连接到系统的终端线路由名为/dev/ttyn的字符设备表示 (对于Linux，设备/dev/ttyn是系统中的虚拟控制台)。因此，通常可以看到tty (源于teletype) 作为终端的简写。

　　在UNIX发展的早期，终端设备并未得到标准化，这表示执行将光标移动到行首或屏幕顶部等操作所需的字符序列不同 (Digital的VT-100等供应商对转义序列的实现逐渐成为了标准，并最终被纳入ANSI标准，但仍然存在着大量其他类型的终端)。标准的缺少表示难以编写能够利用终端特性的可移植程序。编辑器vi就是满足该要求的早期程序之一 (数据库termcap和terminfo记录了如何在各种终端上执行各种屏幕控制操作，而curses库正是为了应对这种标准化的缺失)。

　　现代UNIX系统的常见界面是在高性能位图图形显示器上运行的X Window System (简称X或X11) 窗口管理程序。老式终端提供的功能大致相当于X11中的单个终端窗口 (例如，xterm等窗口)。老式终端的用户与系统之间只有1个 "窗口"，这一事实正是推动作业控制功能开发的动力。同样，曾经很多直接连接到计算机的设备，如今往往已成为通过网络连接的智能设备。

　　传统终端和终端模拟器都有1个关联的终端驱动程序，该驱动程序用于处理设备的输入和输出。

　　当执行输入时，设备能够以规范模式或非规范模式运行 (默认是规范模式)。

　　● 在规范模式下，终端输入按行处理，并且支持行编辑功能。每行以换行符结尾，换行符会在用户按下Enter键时被生成。对终端调用read()只会在完整行可用时返回，并且最多读取1行 (若调用read()时指定的字节数少于当前行的字节数，则剩余字节会在下一次调用read()时返回)。

　　● 在非规范模式下，终端输入不会按行处理 (vi、more和less等程序会将终端切换到这种模式，以便在用户不输入Enter键的情况下读取单个字符)。

　　终端驱动程序也会解释中断符 (通常是Control-C) 和EOF符 (通常是Control-D) 等特殊字符。这种解释会导致为前台进程组生成信号，或者在程序从终端读取时触发某种类型的输入条件。需要将终端切换至非规范模式的程序通常也会禁用部分或全部特殊字符的处理。

　　终端驱动程序会操作用于从终端设备传输到读取进程的输入字符的输入队列和用于从进程传输到终端的输出字符的输出队列。若启用了终端回显，则终端驱动程序会自动将输入字符的副本添加到输出队列的末尾，所以输入字符会出现在终端的输出中。

　　SUSv3详细说明了表示终端输入队列的最大长度的限制MAX_INPUT，相关限制MAX_CANON定义了规范模式下每行的最大字节数。对于Linux，sysconf(_SC_MAX_INPUT)和sysconf(_SC_MAX_CANON)都会返回255，但内核使用的不是这2个限制，而是直接将输入队列限制在4096字节。输出队列的大小也存在相应的限制 (应用程序无需关注该限制，因为当其输出速度快于终端驱动程序的处理速度时，内核会挂起它，直到输出队列有可用空间)。

　　对于Linux，可以通过ioctl(fd, FIONREAD, &cnt)来获取文件描述符fd引用的终端的输入队列中未被读取的字节数，但SUSv3未说明该特性。

62.1 tcgetattr()和tcsetattr()

　　函数tcgetattr()和tcsetattr()会检索和修改文件描述符fd引用的终端的属性。若fd引用的不是终端，则这2个函数会导致错误ENOTTY。

　　参数termios_p指向结构体termios，该结构体用于记录终端的属性。该结构体的前4个成员是用于控制终端驱动程序行为的位掩码：

　　● c_iflag包含用于控制输入的标志。

　　● c_oflag包含用于控制输出的标志。

　　● c_cflag包含与终端线路控制硬件相关的标志。

　　● c_lflag包含用于控制输入的用户界面的标志。

　　成员c_line用于指定终端的行规程。当编写终端模拟程序时，行规程应该总是被设置为N_TTY (即所谓的新规程，它是用于实现规范模式的I/O处理的内核终端处理代码的一部分)。行规程对串口编程很有用。

　　成员c_cc包含终端特殊字符以及用于控制非规范模式输入的字段。数据类型cc_t是足以存储这些值的无符号整数类型。

　　Linux没有使用成员c_ispeed和c_ospeed。

　　当通过tcsetattr()修改终端属性时，参数optional_actions用于控制修改何时生效。该参数可以被指定为标志TCSANOW、TCSADRAIN或TCSAFLUSH。

　　● TCSANOW表示修改立即生效。

　　● TCSADRAIN表示修改会在当前所有排队的输出都被传输到终端后生效。

　　● TCSAFLUSH的修改生效时间与TCSADRAIN相同，但生效时所有待处理的输入都会被丢弃。当需要禁用终端回显并防止用户提前输入时，该标志很有用。

　　修改终端属性的常规方法是通过tcgetattr()检索包含当前设置副本的结构体termios，修改属性，然后通过tcsetattr()将修改后的结构体更新到驱动程序 (这种方法会确保传递给tcsetattr()的是完全初始化的结构体)。

　　如前所述，当后台进程组的进程调用tcsetattr()时，终端驱动程序会发送信号SIGTTOU来挂起该进程组。孤儿进程组的进程调用tcsetattr()会导致错误EIO (这同样适用于本章介绍的其他各种函数)。

　　对于早期UNIX实现，终端属性是通过ioctl()调用访问的。与本章介绍的其他几个函数类似，tcgetattr()和tcsetattr()是POSIX为了解决无法对ioctl()的第3个参数进行类型检查而设计的。对于Linux和很多UNIX实现，它们是ioctl的包装库函数。

62.3.1 CR和DISCARD

　　CR是回车符，该字符会被传递给读取进程。在默认 (即设置了标志ICRNL) 的规范模式下，该字符会在被传递给读取进程之前被转换为换行符。若设置了标志IGNCR，则输入中的该字符会被忽略 (必须在行尾使用真正的换行符)。输出CR字符会导致终端将光标移动到行首。

　　DISCARD是输出丢弃符。尽管数组c_cc定义了该字符，但它在Linux中无效。对于某些UNIX实现，输入1次该字符会导致程序输出被丢弃。该字符是切换开关——再次输入该字符会重新启用输出显示。该字符不会被传递给读取进程。

62.3.2 EOF、EOL和EOL2

　　EOF是规范模式的文件结束符 (通常是Control-D)。在行首输入该字符会导致读取终端的进程遇到EOF。当在行首之外的位置输入该字符时，read()会立即完成，并返回该行迄今为止的字符数。在这2种情况下，EOF都不会被传递给读取进程。

　　EOL和EOL2是额外行分隔符。在规范模式下，它们的作用与NL相同。这些字符默认是未定义的。若它们被定义，则会被传递给读取进程。当设置了标志IEXTEN后 (默认情况)，EOL2才会生效。

　　EOL和EOL2很少使用。telnet就是使用了它们的程序之一。通过将EOL或EOL2设置为telnet转义字符 (通常是Control-J，rlogin模式下则是波浪号~)，即使telnet在规范模式下读取输入，也能立即捕获该字符。

62.3.3 ERASE、INTR和KILL

　　在规范模式下，输入字符ERASE会删除当前行中先前输入的字符。被删除的字符和ERASE不会被传递给读取进程。

　　INTR是中断符。若设置了标志ISIG (默认情况)，则输入该字符会导致信号SIGINT被发送给终端的前台进程组。该字符不会被传递给读取进程。

　　KILL是删除行符。在规范模式下，输入该字符会导致当前行的所有输入被丢弃，所以迄今为止输入的字符 (包括KILL) 都不会被传递给读取进程。

62.3.4 LNEXT

　　LNEXT是字面上的下一个字符 (通常是Control-V)。在某些情况下，可能需要将某个终端特殊字符作为普通字符传递给读取进程。输入该字符会导致下一个字符被视为字面量，所以输入双字符序列Control-V Control-C会向读取进程输入真正的Control-C字符 (ASCII十进制值3)。LNEXT不会被传递给读取进程。在规范模式下，当设置了标志IEXTEN后 (默认情况)，该字符才会生效。

62.3.5 NL

　　NL是换行符。在规范模式下，该字符会终止输入行。NL会被传递给读取进程。输出NL会导致终端将光标移动到下一行。若设置了标志OPOST和ONLCR (默认情况)，则输出中的CR会被映射为CR和NL (标志ICRNL和ONLCR的组合表示输入的CR会被转换为NL并回显为CR加NL)。

62.3.6 QUIT和REPRINT

　　若设置了标志ISIG (默认情况)，则输入QUIT会导致信号SIGQUIT被发送给终端的前台进程组。该字符不会被传递给读取进程。

　　REPRINT是重新打印输入符。在规范模式下，当设置了标志IEXTEN后 (默认情况)，输入该字符会导致终端重新显示当前 (尚未完成) 的输入行。当其他程序 (例如，wall和write) 的输出导致终端显示混乱时，这很有用。

62.3.7 START和STOP

　　START和STOP是开始输出符和停止输出符。当设置了标志IXON后 (默认情况)，这些字符才会生效。有些终端模拟器不支持这2个字符。此外，这2个字符不会被传递给读取进程。

　　输入STOP会挂起终端输出。若设置了标志IXOFF，并且终端输入队列已满，则终端驱动程序会自动生成该字符来限制输入。

　　输入START会恢复之前被STOP停止的终端输出。若设置了标志IXOFF，并且终端驱动程序之前因输入队列已满而生成了STOP，则终端驱动程序会在输入队列有空闲空间时自动生成START。

　　当设置了标志IXANY后，输入任意字符都会重启输出 (该字符也不会被传递给读取进程)。

　　START和STOP可用于计算机与终端设备之间的双向软件流控制。这些字符的用途之一是允许用户停止和启动终端输出 (这是由标志IXON控制的输出流控制)。但是，当终端设备是调制解调器或计算机时，从终端设备到计算机的输入流控制 (由标志IXOFF控制) 也很重要。输入流控制会保证即使应用程序处理输入的速度较慢且内核缓冲区已满，也不会丢失数据。

　　由于如今的行速度通常较高，软件流控制已被硬件 (RTS/CTS) 流控制所取代，后者通过串口上的独立导线发送的信号来启用和禁用数据流。

62.3.8 SUSP和WERASE

　　SUSP是挂起符。当设置了标志ISIG后 (默认情况)，输入该字符会导致信号SIGTSTP被发送给终端的前台进程组。该字符不会被传递给读取进程。

　　WERASE是单词删除符。在规范模式下，当设置了标志IEXTEN后，输入该字符会删除从当前位置到上一个单词 (由字母、数字和下划线组成的字符序列) 开头的所有字符 (对于有些UNIX实现，单词之间的分隔符是空格)。

62.3.9 其他终端特殊字符

　　BSD提供了DSUSP和STATUS字符。

　　● DSUSP (通常是Control-Y) 与SUSP类似，不同之处是前台进程组只会在试图读取该字符时被挂起。有些非BSD衍生实现也提供了该字符。

　　● STATUS (通常是Control-T) 会使内核在终端上显示状态信息 (包括前台进程的状态及其使用的CPU时间) 并发送信号SIGINFO给前台进程组。进程可以按需捕获该信号并显示进一步的状态信息 (Linux通过magic SysRq键提供了与之大致相同的特性)。

　　System V衍生实现提供了SWTCH字符。该字符用于在shell层 (System V中作业控制的前身) 下切换shell。

62.4.1 BRKINT

　　若设置了标志BRKINT，并且未设置标志IGNBRK，则触发BREAK条件时信号SIGINT会被发送给前台进程组。

　　大多数传统哑终端都提供了BREAK键。按下该键不会产生任何字符，而是触发BREAK条件，即向终端驱动程序发送一系列位0，持续指定时间 (通常为0.25或0.5秒，即超过传输1字节所需的时间)。除非设置了标志IGNBRK，否则终端驱动程序随后会向执行读取操作的进程交付值为0的字节。在很多UNIX系统中，BREAK条件的作用是向远程主机发送信号，要求将其线路速率 (波特) 调整为适合该终端的值。因此，用户通常会按住BREAK键，直到出现有效的登录提示符，这表示线路速率已调整至适合当前终端的值。

　　对于虚拟控制台，可以通过按下Control-Break来触发BREAK条件。

62.4.2 ECHO、ECHOCTL、ECHOK和ECHOKE

　　设置标志ECHO会启用输入字符的回显。当输入密码时，禁用回显很有用。在vi的命令模式下，回显也会被禁用，因为此时键盘输入的字符会被解释为编辑命令 (而非文本输入)。该标志在规范模式和非规范模式下均有效。当设置该标志后，设置标志ECHOCTL会导致制表符、换行符、START和STOP以外的控制字符以^A (Control-A) 的形式回显。若未设置ECHOCTL，则控制字符不会回显。

　　控制字符是ASCII码小于32的字符和DEL字符 (十进制值127)。对于控制字符x，系统会将其回显为脱字号^加表达式x ^ 64的计算结果所对应的字符。对于DEL以外的特殊字符，该表达式等同于将字符的数值加上64。对于DEL，该表达式的结果是127减64，得到63 (字符?的ASCII码)。

62.4.3 ICANON和IEXTEN

　　设置标志ICANON会启用规范模式输入。

　　● 输入会按行处理。

　　● EOF、EOL、EOL2、ERASE、LNEXT、KILL、REPRINT和WERASE的特殊解释会被启用。

　　设置标志IEXTEN会启用输入字符的扩展处理。为了解释EOL2、LNEXT、REPRINT和WERASE，必须设置该标志 (以及ICANON)。此外，标志IUCLC的生效也需设置该标志。

　　SUSv3仅说明了IEXTEN会启用扩展 (实现定义的) 功能，其他细节可能因UNIX实现而异。

62.4.4 IUTF8、NOFLSH和OPOST

　　设置标志IUTF8会启用cooked模式，以便在执行行编辑时正确处理UTF-8输入。

　　当通过INTR、QUIT或SUSP生成信号时，终端的输入和输出队列中未被处理的数据默认会被清空 (丢弃)。设置标志NOFLSH可以禁用这种清空。

　　设置OPOST标志会启用输出后处理。当设置该标志后，结构体termios的成员c_oflag中的标志才会生效 (反之，禁用该标志会阻止所有输出后处理)。

62.4.5 PARENB、IGNPAR、INPCK、PARMRK和PARODD

　　标志PARENB、IGNPAR、INPCK、PARMRK和PARODD与奇偶校验的生成和检查有关。

　　标志PARENB会启用输出字符的奇偶校验位生成和输入字符的奇偶校验。若只需要启用前者，则可以禁用标志INPCK来禁用输入奇偶校验。若设置了标志PARODD，则在这2种情况下都会使用奇校验，否则使用偶校验。

　　剩余标志指定如何处理带有奇偶校验错误的输入字符。

　　● 若设置了标志IGNPAR，则该字符不会被传递给读取进程。否则，若设置了标志PARMRK，则该字符会被传递给读取进程，但前面会加上双字节序列0377和0。在这种情况下，若未设置标志ISTRIP，则真正的字符0377会加倍 (变为0377和0377)。

　　● 若设置了标志INPCK，但未设置标志PARMRK，则该字符会被丢弃，并将字节0传递给读取进程。

　　● 若标志IGNPAR、PARMRK和INPCK均未被设置，则该字符会被传递给读取进程。

62.5 终端I/O模式

　　如前所述，终端驱动程序可以在规范模式和非规范模式下处理输入 (取决于标志ICANON的设置)。

62.5.1 规范模式

　　设置标志ICANON会启用规范模式输入。规范模式下的终端输入具有以下特点：

　　● 输入被组织为行，以字符NL、EOL、EOL2、EOF或CR终止。除了EOF之外，其他行分隔符会作为该行的最后1个字符被传递给读取进程。

　　● 行编辑会被启用，以便修改当前输入行，所以字符ERASE、KILL和WERASE (若启用了标志IEXTEN) 会被启用。

　　● 若设置了标志IEXTEN，则字符REPRINT和LNEXT也会被启用。

　　在规范模式下，对终端的read()调用会在整行可用时返回。若read()请求的字节数较少，则它可能仅获取该行的一部分，剩余字节将由后续的read()调用获取。若read()被信号处理函数中断，并且该信号的系统调用重启未启用，则read()会终止。

62.5.2 非规范模式

　　vi和less等应用程序需要在没有分隔符的情况下从终端读取字符。非规范模式正是为此而设计的。在该模式下，系统不会对输入进行特殊处理 (输入不会被组织为行，而是可用)。

　　在非规范模式下，read()会在经过指定时间或/和读取了指定数量的字节后返回。结构体termios的成员c_cc中的元素TIME和MIN (分别由常量VTIME和VMIN索引) 决定这一行为。前者指定十分之一秒为单位的超时时间，后者指定需读取的最小字节数。

　　元素TIME和MIN的行为与相互作用取决于它们各自是否为非0值，共有4种可能的情况。无论哪种情况，若调用read()时已有足够的字节满足MIN指定的要求，则read()会立即返回可用字节数与请求字节数中的较小值。

62.5.2.1 轮询读取

　　当元素MIN和TIME都为0时，read()会立即返回可用字节数与请求字节数中的较小值 (若无字节可读，则立即返回0)。

　　这种情况满足轮询的常规要求，使应用程序以非阻塞方式检查输入是否可用。该模式有点类似于为终端设置标志O_NONBLOCK。但是，当使用该标志时，read()会在无字节可读时出错 (EAGAIN)。

62.5.2.2 阻塞读取

　　当元素MIN大于0，元素TIME为0时，read()可能会阻塞进程，直到可用字节数达到请求字节数或MIN中的较小值，然后返回该值。

　　less等程序通常会将MIN和TIME分别设置为1和0。这允许程序在不通过忙循环轮询浪费CPU时间的情况下等待单次按键输入。

　　若将终端设置为非规范模式，并将MIN和TIME分别设置为1和0，则可以使用备选I/O模型来检查终端上是否输入了单个字符。

62.5.2.3 带超时的读取

　　当元素MIN为0，元素TIME大于0时，调用read()会启动定时器。当至少有1个字节可用或经过TIME的十分之一秒后，该调用会返回。对于后者，该调用会返回0。

　　这种情况适用于与调制解调器等串行设备通信的程序。程序可以向设备发送数据并等待响应，并使用超时机制防止设备无法响应导致程序无期限被挂起。

62.5.2.4 带字节间超时的读取

　　当元素MIN和TIME都大于0时，read()会在读取第1个字节后启动定时器，后续每次读取1个字节都会重置定时器。若读取的字节数达到了MIN和请求字节数中的较小值，或者接收连续字节之间的时间超过TIME的十分之一秒，则read()会返回。由于定时器在读取第1个字节后启动，所以至少会返回1 (在这种情况下，read()可能会无期限地阻塞进程)。

　　这种情况下适用于处理会生成转义序列的终端键 (例如，对于很多终端，左箭头键会生成由Escape和OD组成的序列)。转义序列会快速连续地被传输。处理这种序列的应用程序需要区分快速按下该键的情况和用户缓慢输入每个字符的情况。这可以通过执行带有较短字节间超时的read()来实现。某些版本的vi就采用了该技术 (根据超时时间的长短，在这种应用程序中，或许可以通过快速输入字符序列来模拟按下左箭头键)。

62.5.2.5 可移植地修改和恢复元素MIN和TIME

　　为了保持与某些UNIX实现的历史兼容性，SUSv3允许常量VMIN和VTIME的值与VEOF和VEOL相同，这表示结构体termios的成员c_cc中的这些元素可能重叠 (对于Linux，这些常量的值各不相同)。允许这种情况是因为在非规范模式下VEOF和VEOL未被使用。

　　由于VMIN和VEOF的值可能相同，所以在进入非规范模式、设置MIN，然后返回规范模式的程序中需要谨慎处理。当回到规范模式后，EOF将不再具有通常的ASCII值4 (Control-D)。解决该问题的可移植方法是在切换到非规范模式之前保存结构体termios的副本，随后通过该结构体切回规范模式。

62.6 终端行速度

　　术语波特通常被用作终端行速度 (比特/秒) 的同义词，尽管从技术角度这种说法并不准确。确切地说，波特是线路上的信号每秒变化的速率，这不一定等同于每秒传输的比特数，因为后者取决于比特是如何被编码成信号的。尽管如此，波特仍然常被用来指代比特率 (人们也常把 "波特率" 与 "波特" 混用，但这是多余的，波特本身就是速率的定义)。为了避免混淆，后续的内容通常会使用术语行速度或比特率。

　　不同的终端 (和串口线) 能够以不同的速度 (位/秒) 传输和接收。函数cfgetispeed()和cfsetispeed()会检索和修改输入行速度，函数cfgetospeed()和cfsetospeed()会检索和修改输出行速度。

　　这些函数的参数termios_p指向的结构体必须是之前通过调用tcgetattr()获取的。

　　数据类型speed_t用于存储行速度。程序通常不会直接为行速度赋值，而是使用头文件termios.h中定义的常量。这些常量定义了一系列离散值 (例如，常量B9600和B38400分别对应行速度9600和38400比特/秒)。采用这些离散值反映了事实：终端通常被设计为仅支持几种标准线路速率，这些速率是通过将某个基准速率除以整数值而得出的 (例如，115200 / 12 = 9600)。

　　SUSv3规定终端行速度被存储在结构体termios中，但 (故意) 未说明具体成员。Linux等很多实现都将该值存储在成员c_cflag中，并使用掩码CBAUD和标志CBAUDEX。

　　尽管函数cfsetispeed()和cfsetospeed()允许单独指定输入和输出行速度，但是对于很多终端，它们必须相同。此外，Linux仅使用了单个成员来存储行速度。

62.7 终端行控制

　　函数tcsendbreak()、tcdrain()、tcflush()和tcflow()执行的任务通常统称为行控制。这些函数是POSIX提出的，旨在取代各种ioctl()操作。

　　对于每个函数，参数fd都是引用终端或其他通过串口线连接的远程设备的文件描述符。

　　函数tcsendbreak()会通过传输不间断的位0流来触发BREAK条件。参数duration指定传输的时长。

　　● 若该参数为0，则传输0.25秒的位0流 (SUSv3要求该时长至少为0.25秒，并且不超过0.5秒)。

　　● 若该参数大于0，则传输该参数指定的毫秒数 (SUSv3未说明该情况，并且该时长因UNIX实现而异，这里介绍的是glibc的行为)。

　　函数tcdrain()会阻塞调用进程，直到所有输出都已被传输 (即终端输出队列为空)。

　　函数tcflush()会刷新终端输入队列和/或输出队列。刷新输入队列会丢弃已被终端驱动程序接收但尚未被进程读取的数据。刷新输出队列会丢弃已被传递给终端驱动程序但未被传输给设备的数据。参数queue_selector可以被指定为以下值之一：

queue_selector值描述
TCIFLUSH刷新输入队列
TCOFLUSH刷新输出队列
TCIOFLUSH刷新输入和输出队列

　　函数tcflow()用于控制计算机与终端 (或其他远程设备) 之间的任一方向的数据流。参数action可以被指定为以下值之一：

action值描述
TCOOFF挂起到终端的输出
TCOON恢复到终端的输出
TCIOFF传输1个STOP字符到终端
TCION传输1个START字符到终端

　　当终端能够解释STOP和START字符时，值TCIOFF和TCION才会生效。

62.8 终端窗口大小

　　在窗口环境中，屏幕处理应用程序需要监控终端窗口的大小，以便在用户修改窗口大小时重绘屏幕。内核提供了2种支持机制：

　　● 当终端窗口大小发生变化时，信号SIGWINCH会被发送给前台进程组 (该信号默认会被忽略)。

　　● 进程随时 (通常是收到信号SIGWINCH之后) 可以通过ioctl()的操作TIOCGWINSZ获取终端窗口的当前大小。

62.9 终端标识

　　函数isatty()可用于判断文件描述符fd是否与终端关联。

　　函数ttyname()会返回文件描述符fd引用的终端的名称。该函数会通过opendir()和readdir()遍历终端名所在的目录。它会逐一检查目录项，直到找到设备ID (结构体stat的成员st_rdev) 与fd引用的设备ID匹配的条目。终端设备条目通常位于目录/dev和/dev/pts (前者包含虚拟控制台和BSD伪终端的条目，后者包含System V风格的伪终端从设备的条目)。ttyname()的可重入版本是ttyname_r()。

　　命令tty可用于显示其标准输入对应的终端的名称。
